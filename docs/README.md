# Documentation Guide

This directory is the entry point for documentation written for developers and
AI coding agents.

## Start Here

Read only what the current task needs:

| Task | Read |
|---|---|
| Understand or integrate the API | [`api/README.md`](api/README.md) |
| Deck upload, processing, or slides | [`api/decks.md`](api/decks.md) |
| Grounded tutor chat | [`api/chat.md`](api/chat.md) |
| Generated learning maps | [`api/mindmaps.md`](api/mindmaps.md) |
| Lessons or ingestion jobs | [`api/lessons-and-jobs.md`](api/lessons-and-jobs.md) |
| Add an API domain document | [`templates/api-domain-template.md`](templates/api-domain-template.md) |

Do not load every document by default. Start at the API index, then read the
relevant domain document and the files listed in its `source_of_truth`.

## Source of Truth

When sources disagree, use this priority:

1. Registered FastAPI routes and Pydantic schemas.
2. Tests demonstrating observable behavior.
3. OpenAPI generated by the running application.
4. Markdown in this directory.

Markdown explains the implementation. It must not invent absent behavior.
Report a mismatch instead of guessing.

## Required Metadata

Every API domain document starts with:

```yaml
---
title: Human-readable title
status: draft | implemented | deprecated
last_verified: YYYY-MM-DD
source_of_truth:
  - path/to/route.py
  - path/to/schema.py
  - path/to/test.py
---
```

Paths are repository-relative. `last_verified` means the document was compared
with all listed sources on that date.

## Writing Rules

- Write prose in English.
- Preserve exact paths, identifiers, fields, enum values, and status codes.
- Explain preconditions and state transitions before examples.
- Include a successful example and important failures with retry guidance.
- Explain polling and terminal states for asynchronous APIs.
- State types and constraints only when verified in source.
- If a route returns an untyped `dict`, describe verified output and flag the
  limitation; do not claim an inferred schema is stable.
- Do not document auth, guarantees, or side effects that are not implemented.
- Use synthetic examples. Never copy secrets or private data.

## Agent Update Workflow

1. Read `server/app/main.py` and the relevant router.
2. Read the route, schemas, and behavioral tests.
3. Compare with `/docs` or `/openapi.json` when the server is available.
4. Update the domain document and `api/README.md`.
5. Update `last_verified`.
6. Record unresolved conflicts under **Known Limitations**.

An API code change is incomplete until its affected documents are updated.

## Review Checklist

- [ ] Every registered endpoint appears in `api/README.md`.
- [ ] Methods, paths, status codes, and examples match source.
- [ ] Request constraints match Pydantic models.
- [ ] Async and retry behavior is explicit.
- [ ] Every `source_of_truth` path exists.
- [ ] Untyped responses are not presented as guaranteed schemas.
- [ ] `last_verified` is current.

## Drift Prevention

Drift checking is manual for now. A future phase should export a deterministic
OpenAPI snapshot and compare it in GitHub Actions.
